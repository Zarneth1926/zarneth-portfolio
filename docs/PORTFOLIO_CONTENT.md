**Project Name:**  
GenHub

**Full Title:**  
GenHub — Web-Based Barangay Information and Concern Management System

**Project Type:**  
Capstone Project / Full-Stack Web Application

**Role:**  
Developer

**Status:**  
Active Development

**Portfolio Priority:**  
Flagship Project

**Short Description:**  
GenHub is a web-based barangay information and concern management system designed to make barangay services more accessible to residents while helping barangay personnel manage service requests, resident information, announcements, events, and administrative workflows.

**Problem:**  
Many barangay transactions require residents to visit the barangay office for document requests, updates, and other services. GenHub aims to provide a more convenient digital workflow for residents while giving barangay personnel a centralized system for managing requests and community information.

**Main Users:**
- Residents
- Barangay Staff
- Barangay Secretary
- Barangay Captain

**Implemented / Current Features:**
- Resident registration and verification
- Role-based authentication
- Barangay document and service requests
- Request status tracking
- Document upload
- Resident profile management
- Announcements
- Events
- Notifications
- Admin resident management
- Request review and approval workflow
- Barangay information management
- Password recovery through email verification

## 13. Public Content & Implementation Rules

All portfolio content must be based on real information.

### Never Fabricate
- employment experience
- internships
- clients
- testimonials
- certifications
- awards
- production-user counts
- project statistics
- credential IDs
- employment history
- technical achievements or metrics

### Incomplete Content

Internal placeholders such as:
- `To be added`
- `To be finalized`
- `Pending`
- `In Progress`

may remain in this master document.

They must **not** appear as unfinished labels or dead buttons on the public website.

Instead:
- hide unavailable links
- omit incomplete cards
- disable nothing unless there is a clear user-facing reason
- render only verified content that is ready for visitors

### Privacy

Do not publish:
- personal phone number unless explicitly approved later
- full home address
- government IDs
- school IDs
- passwords
- API keys
- private tokens
- private account information

### Accuracy Standard

Accuracy is more important than making the portfolio appear more impressive.

When information is incomplete, leave it out of the public interface until it is ready.
